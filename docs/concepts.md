## 1. 프로젝션
SELECT 뒤에 적은 컬럼만 골라내는 단계입니다.

```txt
SELECT name, age FROM users;
행    = ["1", "김철수", "25", "a@b.com"]   (id, name, age, email)
결과  = ["김철수", "25"]
```

## 2. B+ 트리
- **내부 노드**는 길을 안내하는 경계 키만 갖고, **리프 노드**가 실제 값을 갖습니다.
- 노드가 넘치면 반으로 나누고 경계 키를 부모로 올립니다. 그래서 모든 리프의 깊이가 같습니다.

### 실제 DBMS와의 차이
- **실제 DBMS**: 노드 하나가 고정 크기 디스크 페이지입니다(PostgreSQL 8KB, InnoDB 16KB, SQLite 4KB 기본). 페이지 안의 키는 슬롯 배열로 정렬합니다.
- **우리**: 메모리 기반으로 단순화했습니다.
- **노드 크기**
  - MySQL(InnoDB)은 노드를 디스크에서 읽는 비용이 커서 노드를 크게(키 수백 개) 만들고 층수를 줄입니다.
  - 우리는 노드 읽기가 싸서 노드 안 비교 비용이 상대적으로 커지므로, 64~128 정도가 적당했습니다.

## 3. 외부 클라이언트
- 기준은 컴퓨터가 아니라 **프로세스가 분리되어 있는지**입니다. 같은 컴퓨터여도 포트로 통신하면 외부입니다.

```txt
내부: 엔진.execute("SELECT ...")      ← 같은 프로그램 안, 함수 호출
외부: curl localhost:8080/query ...    ← 다른 프로그램, 네트워크 요청
```

- 실제 MySQL도 서버(mysqld)는 3306 포트에서 대기하고, Spring 앱이나 DBeaver는 따로 실행되는 클라이언트입니다. 우리는 127.0.0.1:8080에서 HTTP로 받습니다.

<br/>

## 4. 동시성 기본 개념
- **스레드 풀**: 요청마다 스레드를 새로 만들지 않고, 미리 만든 스레드를 재사용하는 구조입니다.
- **경쟁 상태(race condition)**: 여러 스레드가 같은 데이터를 동시에 건드릴 때 생기는 문제입니다.
- **락(mutex)**: 한 번에 한 스레드만 들어가게 해서 경쟁 상태를 막는 방법입니다.
